# Data-driven heuristics

`orgscan scan path ./target --scanner heuristic-rules` runs the registered rule-driven scanner. It reuses the custom-pattern scanner's file enumeration and size limit while leaving existing `custom-patterns`, history patterns and ripgrep detections intact. Default scan/profile selections are unchanged. CLI, artifact API and jobs discover the adapter through the registry.

`ORGSCAN_HEURISTIC_RULES_PATH` selects an operator-authored UTF-8 JSON array; absent configuration uses `src/orgscan/scanners/rules/starter.json`. Configured rules replace the starter set. Copy/edit that file to add most detectors without changing Python. Fields are `id`, `title`, `category`, `severity`, `confidence`, `regex`, `include`, `exclude`, `description`, and `remediation`. Include defaults to `*`; excludes win. Patterns match the target-relative POSIX path (Python fnmatch semantics). Unknown schema fields, invalid regex, duplicate IDs and empty-string matches fail with file/rule diagnostics that omit raw input values.

Rules are limited to 100 objects, 1 MB per file and 4096 characters per regex. Each rule/line match operation uses `ORGSCAN_HEURISTIC_MATCH_TIMEOUT_SECONDS` (0.05 seconds by default, maximum 5). The [regex engine](https://github.com/mrabarnett/mrab-regex#timeout) supplies the timeout. A timeout fails the scan rather than silently producing incomplete successful evidence. Files over 1 MB, non-UTF-8/binary content, `.git` data and symlinks are excluded. Overall scan duration still scales with file/rule counts; this is not a whole-job CPU budget.

The five starters target internal hostname suffixes, credential-bearing database URIs, private-key headers, AWS resource identifiers and privileged YAML deployments. They are deliberately heuristic findings requiring review, not proof of ownership or exploitability.

Indicators and snippets are fully redacted. Non-secret matches carry a stable SHA-256 observation digest; secret rules with a named `(?P<value>...)` group carry a digest of the isolated credential value for correlation. Secret structural markers retain location identity without a value digest. Structural markers such as private-key headers do not claim to identify a complete secret. No source lines/raw matched strings are retained. Configured rule-file content changes invalidate incremental checkpoints through the registry's declared file setting. Built-in file-based rules should be versioned with releases.
